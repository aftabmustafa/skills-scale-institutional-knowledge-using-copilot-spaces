# OctoAcme Project Management Documentation

## Overview

OctoAcme uses a structured project lifecycle designed to move work from initial idea to delivery, release, and continuous learning. New projects begin with a lightweight initiation phase that validates the business need, aligns stakeholders, and defines measurable outcomes before the team commits to deeper planning. Once approved, the work is broken into prioritized backlog items, clear milestones, and iterative delivery increments with explicit ownership, dependencies, and acceptance criteria. Throughout execution, the team follows a team rhythm that includes daily standups, weekly delivery reviews, and milestone demos to keep work visible, unblock decisions, and maintain delivery momentum.

The core OctoAcme approach emphasizes customer value, iterative delivery, and data-informed decision-making. Each project has a named Project Manager and Product Lead, and teams are expected to manage work through transparent planning, ongoing risk management, and quality checks at every stage. Communication is treated as a first-class project activity, with documented cadences, stakeholder updates, escalation paths, and a single source of truth for status. Quality is built into delivery through unit testing, integration testing, smoke tests, CI validation, and security checks before release. After each sprint or significant milestone, the team reflects on outcomes and converts lessons into action items so the process improves over time.

## Core principles

- Customer-first: prioritize customer value and usability.
- Iterative delivery: deliver small, testable increments.
- Clear ownership: each project has a named Project Manager (PM) and Product Lead.
- Data-informed decisions: measure impact and iterate based on evidence.
- Psychological safety: encourage feedback and learning.

## Project lifecycle documentation

The documents in this folder work together as a complete project management system. Use them in sequence as a project moves from idea to execution and release.

### 1. [Project Management Overview](octoacme-project-management-overview.md)
A concise introduction to OctoAcme's approach for new teammates and stakeholders.
- Covers scope, principles, personas, lifecycle, communication cadence, and project artifacts.
- Use this as the first document for orientation when joining a project or onboarding to OctoAcme practices.

### 2. [Project Initiation Guide](octoacme-project-initiation.md)
Defines how to validate and authorize a new initiative before planning begins.
- Covers business need, stakeholder alignment, success metrics, and the initial project one-pager.
- Use this when a new project idea or feature proposal is ready to be explored and a go/no-go decision is needed.

### 3. [Project Planning](octoacme-project-planning.md)
Turns an approved initiative into an actionable plan and delivery backlog.
- Covers kickoff meetings, backlog creation, estimation, definition of done, dependency management, and release planning.
- Use this after initiation approval to create the detailed plan for execution.

### 4. [Execution & Tracking](octoacme-execution-and-tracking.md)
Guides day-to-day execution and milestone tracking.
- Covers daily standups, weekly delivery syncs, demos, PR workflow, testing expectations, and blocker escalation.
- Use this throughout build and delivery to keep the project on track and visible to stakeholders.

### 5. [Risk Management & Communication](octoacme-risks-and-communication.md)
Explains how to identify, assess, and communicate project risk and dependencies.
- Covers the risk register, escalation paths, stakeholder communications, and incident communication templates.
- Use this whenever a project needs structured communication or risk tracking.

### 6. [Release & Deployment](octoacme-release-and-deployment.md)
Standardizes how features move to production with reduced risk and better observability.
- Covers release types, pre-release requirements, deployment checklists, rollback plans, and release notes.
- Use this when work is ready for staging or production deployment.

### 7. [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)
Captures learning and turns it into sustained process improvement.
- Covers retrospectives, action items, follow-up tracking, and continuous improvement culture.
- Use this after each sprint, release, or major milestone to improve how the team works.

### 8. [Roles & Personas](octoacme-roles-and-personas.md)
Defines the typical roles used across OctoAcme project work and their responsibilities.
- Covers developers, product managers, project managers, and how those roles interact.
- Use this to clarify responsibilities, communication patterns, and decision ownership for a project team.
